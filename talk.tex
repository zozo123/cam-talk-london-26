\item Their attempts may conflict, duplicate effort, or produce dependent evidence.
\item A system must preserve what changed and govern what enters shared state.
\end{itemize}
\claim{The challenge is to turn parallel agency into coordinated, assessable work.}
\note{[0:50] The motivation is a change in how we use capable models. We increasingly connect them to tools and let them take sequences of actions, not just return one answer. Once several agents or processes can act at once, coordination becomes a systems problem: what state did each inherit, what did it change, what can others learn from its result, and who can commit a change? The talk studies a runtime layer that can make those questions explicit. This is a research motivation, not a claim that every multi-agent system needs the same architecture.}

% 06
\begin{frame}[t]{Branches in biology; forks in software}
\begin{columns}[T,onlytextwidth]
\column{.48\textwidth}
\term{Arp2/3 in an actin network}
\begin{itemize}
\item Nucleates a daughter filament from a mother filament.
\item Local branching changes network connectivity.
\item Interactions shape collective structure and dynamics.
\end{itemize}
\column{.48\textwidth}
\term{A fork in a computational experiment}
\begin{itemize}
\item Restore a declared, supported parent state.
\item Apply a recorded intervention and randomness policy.
\item Keep each continuation's outcome and lineage.
\end{itemize}
\end{columns}
\vspace{.1cm}
\[
C_i=\operatorname{Continue}(\widehat S_0,\Delta_i,\omega_i)
\]
\small $\Delta_i$: candidate change; $\omega_i$: declared random-stream policy.
\claim{Physical branching motivates the question; it does not define software semantics.}
\sources{Biology: \href{https://www.pnas.org/doi/10.1073/pnas.1922494117}{Liman et al., PNAS (2020)}; runtime proposal: \href{https://arxiv.org/abs/2607.09689}{Eliaz (2026), preprint}.}
\note{[1:05] Arp2/3 gives us a physical reason to take branching seriously. It nucleates a daughter actin filament from a mother filament; that local event changes the network's connectivity, and network interactions shape larger-scale behavior. A computational fork is a different operation: it resumes a supported state into separate executions. We can describe one child as a continuation of a captured parent under a declared change and random-stream policy. The analogy is about shared history, branching structure, and interactions. It does not say molecules copy a machine state, that the child computations interact like filaments, or that a biological branching threshold predicts software performance. The later biology slide will return to the empirical results.}
\end{frame}

\begin{frame}[t]{What belongs to the state?}
\lead{Reproducing a continuation requires more than a filesystem copy.}
\[
S_t=(F_t,\ M_t,\ H_t,\ R_t\ ;\ X_t)
\]
\begin{tabularx}{\textwidth}{@{}L{3.5cm}Y@{}}
$F_t$: files and artifacts & Repository, dependencies, fixtures, build outputs.\\
$M_t$: machine state & Processes, memory, supported devices and runtime state.\\
$H_t$: agent history & Messages, tool results, policy identity, pending decisions.\\
$R_t$: randomness & Generator state and declared reseeding policy.\\
$X_t$: external state & Services, clocks, identities, devices, physical systems.\\
\end{tabularx}
\claim{A capture manifest identifies what is copied, reconstructed, or left external.}
\note{[1:00] This is a conceptual state decomposition, not a promise that one snapshot format captures all components. A VM snapshot may preserve process memory yet leave the agent's remote conversation history outside it. A copied random generator creates a coupling until streams diverge or are explicitly reseeded. External service state needs a declared policy: freeze a fixture, replay responses, recreate the service, or accept an uncontrolled dependency. The manifest makes those choices auditable.}
\end{frame}

% 09
\begin{frame}[t]{A continuation contract}
\lead{Restoration should preserve the behavior relevant to the task.}
\[
 d\!\left(\mathcal{L}(O^{\pi}_{\mathrm{restored}}),
           \mathcal{L}(O^{\pi}_{\mathrm{direct}})\right)\leq\varepsilon
\]
\vspace{.15cm}
\begin{itemize}
\item Fix the continuation policy $\pi$, observation boundary $O$, and external-state policy.
\item Choose a task-relevant distance $d$ and tolerance $\varepsilon$.
\item Check declared invariants before measuring search performance.
\end{itemize}
\vspace{.2cm}
\tagline{Example: identical parser fixtures and outputs; bounded timing variation.}
\claim{A successful restore is the beginning of a fidelity test.}
\note{[1:15] This is a proposed observational contract. The law symbol denotes the distribution of observations under the declared continuation, not equality of every machine bit. For deterministic tests we may require exact agreement; stochastic simulations need a justified distributional criterion. Finite tests check specified observations and cannot certify every possible policy or event. Restoration fidelity, candidate quality, and scientific validity are separate axes. We establish the first before attributing an outcome to a changed candidate.}
\end{frame}

\item Invalidate artifacts affected by the intervention.

Content-addressed build artifacts can be shared with explicit scope and provenance. This lifecycle is also why restore latency alone is a poor measure of useful search cost.}

\begin{frame}[t]{When does branching pay?}

\[

\claim{$(N-1)P>H+N(R+D)$}

\begin{frame}[t]{Evidence-aware reduction}
