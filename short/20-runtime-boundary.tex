\claim{Record effects once. Keep the publish key outside every fork.}
\sources{Output commit: Speculator, external synchrony, Remus. Effect journal: proposed. Publish path: our factory runs.}
\qadetail{Restoring state cannot unsend a model or tool request, refund its cost or reverse a completed remote action; staging a patch keeps local bytes, while publication still needs a separate gate. An effect cannot be computed once by restoring; it can only be recorded once, outside the child. Speculator, external synchrony and Remus are precedents for delaying output; DSec replays cached command results on resumption. A general effect journal is proposed, not built: stage effects where possible, reconcile uncertain outcomes, and use idempotency keys when the remote service supports them; an uncertain remote action cannot be blindly retried. Export the patch, inputs and receipts before every teardown, including refusal (motivated by SELFHOST-3). MEASURED scope: the factory runs (Docker Sandboxes via Airflow, serial, nothing forked) exercised one controller-mediated publication path with sha256-bound approval: the worker returned a patch and test records, and the controller checked approved bytes and held the publish key; they did not intercept every external effect. DESIGN scope: fresh clone authority, host authentication and authorization of each child outside copied guest state, revocable authorization and epoch fences are proposed. A fork copies every credential or capability in the guest: a microVM can contain a still-valid bearer token, and kernel isolation does not make that token harmless; so the publishing credential must never be placed in the guest. Guest-supplied generation strings are copied and cannot authenticate a clone, and fresh identity alone does not confer authority. Egress policy is distinct from withholding publication credentials. Siblings restored from one snapshot share every guest value: idempotency keys, userspace RNG state, boot_id, machine-id, MAC. A copied key would let a service merge N alternatives into one request; cloned userspace RNG can repeat nonces (Ristenpart and Yilek, NDSS 2010). VMGenID can reseed the kernel; userspace RNG treatment is application-dependent. H1 records boot_id, machine-id, IP/MAC, guest-minus-host clock and a userspace random value per cell (PREREGISTRATION.md, Phase A). Output-commit precedents: Speculator (Nightingale, Chen and Flinn, SOSP 2005), external synchrony (Nightingale et al., OSDI 2006), Remus (Cully et al., NSDI 2008). Capability systems that bound what a credential can do: Capsicum, CHERI.}
\note{[1:05] First, remote effects. Save a sandbox, call a hosted model, then restore. The sandbox is back, but the model has already answered and charged us. A restore cannot rewind another service. So an effect is not computed once, but recorded once, outside the child. Our proposed design retries with an idempotency key. The controller gives each child its own key, so forks never share one. Second, credentials. A fork copies every credential inside the sandbox. So the publish key must stay outside. The worker returns a patch and its test records. Only the controller holds that key. Our factory runs exercised that separation. Rule two: count once.}
