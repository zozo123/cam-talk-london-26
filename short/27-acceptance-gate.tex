\qadetail{DESIGN scope: the gate is proposed and builds on the built sha256-bound publication check. Step 1 freezes the candidate and its hash: the hash that keyed the cache now names the bytes the controller may publish. A valid digest proves identity, not correctness. Step 2 requires and runs a test for each promise the change makes, on those exact files. For the factory patch, the required test forces CellBusy with an active workspace owned by another attempt of the same job, holds the current dispatch authorization and asserts one backend dispatch; if no test exercises a promise the change makes, the gate refuses. Promises come from the approved plan and from review findings; a change outside the plan's files needs explicit scope authorization plus its own test. A test counts only if it forces the path and asserts the promise (CellBusy, same job, one dispatch); execution without the assertion does not. In this case the gate refuses on both grounds: scope (service.py was outside the six approved files) and a reviewer-named promise with no test. Step 3: the controller publishes only the frozen hash; that hash-bound publish check is built. Scope authorization, an executed receipt, behavioral coverage, exact-composition verification, artifact-bound approval and current controller authority are separate obligations. The suite in the factory run did run on the exact candidate bytes and was green; the gate addresses the missing promise test, not changed bytes.}
