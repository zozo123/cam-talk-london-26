\qadetail{Autoresearch: one reported session, not a controlled average effect or a fork experiment. 126 attempts: 23 kept, 102 discarded (reverted), 1 crash. The score decline is (0.997900-0.969686)/0.997900=2.827\%; lower validation bits per byte is better. The protocol holds data preparation, tokenizer and evaluation fixed and permits editing train.py. Five minutes is wall-clock training time; startup and compilation are outside that budget, and crashes can end early. Sequential Git keep/revert is the actual mechanism; forked parallel continuations are a possible extension, not what produced this result. Compute once here means the fixed preparation and the incumbent commit are reused rather than rebuilt; it is not a measured saving. Count once: every keep-or-revert decision used the same validation set, so the 126 scores are not 126 independent checks; repeated adaptive selection on one validation set warrants a separate held-out check before claiming generalization. Publish once: only a kept commit advances the incumbent, one change at a time. AlphaEvolve: DeepMind reports that the discovered Borg scheduling heuristic recovered an average 0.7\% of Google's worldwide compute resources; this measures the discovered rule, not sandbox forking.}
\note{[1:20] First, one real example: Karpathy's autoresearch. An AI agent tries to improve a language model. It may edit only one file, the training script. Data preparation, the tokenizer and the evaluator are fixed. They are set up once. Every attempt starts from the best commit so far. That is compute once. In one reported session, the agent made a hundred twenty-six attempts. Every score came from the same validation set. That set is one shared observation, reused again and again. So the gain needs a separate held-out check. That is count once. After each five-minute run, the agent keeps the change or reverts it in Git. Twenty-three were kept, a hundred two reverted, and one crashed. A kept change becomes the new best commit. That is publish once. The score fell 2.8 percent. The loop ran one attempt at a time, with no forks. AlphaEvolve runs the same loop over a population of programs. Now four more fields.}
