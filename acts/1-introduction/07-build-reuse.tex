Full test path approximately75s fresh and43s restored, while Cargo after touching source was approximately38s versus13s restored Incredibuild. These are cache endpoints, not memory-checkpoint or fork timings; no maintainer adoption claim. }
\note{[0:45] In a reported Tokio build demo, a fresh compile took roughly forty-six seconds. Restoring the artifact cache brought it to thirteen seconds; a hot cache took roughly three. This is static artifact reuse, with approximate timings from my external demonstration. It establishes the motivation: reconstruction can dominate useful work, and reuse changes the cost. A live-state fork must earn its place against an equivalent warm baseline for its workload, not only against the cold start.}
