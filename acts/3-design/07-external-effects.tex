\qadetail{The original effect table retains three cases: sending a model request incurs the remote invocation and its cost; sending a tool request may complete a remote action; staging a patch retains local bytes while publication still needs a separate gate. State restoration cannot unsend an invocation or reverse a completed remote effect. Speculator, external synchrony and Remus supply precedents for delaying output. DSec can replay cached command results on resumption. A general effect journal and buffer is proposed here: stage effects where possible, reconcile uncertain outcomes, or use idempotency when the remote service supports it. An uncertain remote action cannot be blindly retried. Export patch, inputs and receipts before every teardown, including refusal; this recovery rule is motivated by SELFHOST-3. The factory exercised one controller-mediated publication path and did not intercept every external effect.}
\note{[0:45] A snapshot controls the guest state. A completed request to a hosted model is already outside that boundary, and its cost has been incurred. Restoring the guest cannot reverse that invocation. The same issue applies when a remote tool may have completed an action. We need to record the outcome and reconcile uncertainty before retrying. Some effects can be staged; supported idempotency can make others safe to repeat. A general effect buffer remains a design. Local restoration therefore needs an explicit external-effect policy.}
