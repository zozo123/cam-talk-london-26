\begin{frame}{An epoch check rejects the old instance after worker replacement.\ev{\tagP}}

\begin{ticks}\item Approval binds one frozen artifact.\item Concurrent fork gets a new worker identity and its own epoch.\end{ticks}
\claim{The controller checks authority outside the restored guest state.}
\sources{Proposed promotion protocol; Gray \& Cheriton, Leases, SOSP 1989.}
\qadetail{This is a proposed epoch-fenced publication protocol, not an implemented or model-checked result. A TLA+ design exists; no TLC run or implementation trace check is recorded. The controller checks authenticated identity, current epoch, expiry, artifact, scope and budget. Evidence, approval and publication must name one frozen artifact. Replacement and concurrent fork are distinct: replacing logical worker w invalidates its old epoch; a new child identity need not revoke a continuing parent. Fresh identity alone does not confer authority. Intended model covers clone, lease expiry, delayed approvals and uncertain effects. State restoration and authority renewal are coupled protocol events.}
\note{[0:55] A logical worker starts with authority at epoch one. When the controller replaces that worker, it advances the current epoch to two. A delayed publication from the old instance carries epoch one, so the controller rejects it. Approval also names the frozen artifact, and the controller checks scope, expiry and budget. A concurrent fork receives a new worker identity and its own epoch; the parent may continue with its existing authority. This epoch protocol has a TLA plus design and still needs model and implementation checks. Execution can preserve state while publication remains a current controller decision.}
\end{frame}
