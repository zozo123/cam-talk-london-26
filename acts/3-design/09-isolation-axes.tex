\claim{Pick the kernel surface for the workload. Hand over authority explicitly.}
\sources{\href{https://github.com/MoonshotAI/Kimi-K3}{Kimi K3} \S5.3.2; Firecracker production host setup guide; Watson et al., Capsicum (USENIX Sec'10) and CHERI (IEEE S\&P'15).}
\note{[0:50] Child isolation has two axes, and this laboratory built systems for both. A container shares one kernel. gVisor moves it to user space. A microVM stands on a hypervisor. An ordinary process names whatever its user can. Under Capsicum or CHERI, it uses only what it is handed. A build cache may be shared within one trust domain of equally trusted code. Scratch is never shared. Kimi saw kernel panics in early container runtimes. Firecracker advises disabling SMT and same-page merging.}
