\qadetail{The documented 10--20x gain is for persistent mode, which avoids a process fork for every input. It must not be attributed solely to the deferred forkserver. The forkserver can defer cloning until expensive initialization is complete; a persistent child then repeatedly executes the harness, resetting mutable state between inputs. The documentation recommends roughly 1,000 iterations before restarting to contain leaks and residual state. Coverage and stability checks can expose state-reset mistakes. A newly executed input is not automatically an independent observation, and a crash is not automatically an exploitable vulnerability. This is a published defensive testing workflow, not our benchmark or an instruction to attack a live service. AFL++ is a coverage-guided fuzzer descended from American Fuzzy Lop. Input mutations are tested against an instrumented target, and coverage feedback retains promising inputs for further mutation. Crashing inputs require investigation and deduplication. The technical whitepaper describes the foundational AFL mechanisms and labels itself outdated; current persistent-mode documentation supplies the restart recommendation and performance scope. The fuzzer maintains the input corpus; the target harness resets mutable state between persistent iterations.}
